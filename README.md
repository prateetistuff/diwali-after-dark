# Diwali After Dark

A mobile-first, 4–16-player Diwali murder mystery. One host shares a room code; each friend plays on their own device. Dark festive colours, gold accents, serif type, non-graphic shadow scenes and original synthesised music.

This is a complete source export of deployed version 3, source commit `6757dd0eeb71ab62b525a9a43a240b72db33922e`. Game logic, visuals and assets are preserved. Only personal Site identity has been removed; documentation and portable setup helpers have been added. The existing hosted game has not been changed by this export.

## What is included

- `app/page.tsx`, `components/`, `app/globals.css`: interface, responsive styling, smart chat scrolling, animated scenes and letters.
- `app/api/game/route.ts`: server API, room creation/joining, recovery, persisted state and concurrency checks.
- `lib/game/engine.ts`: roles, cryptographic shuffling, clues, four-phase rounds, secret actions, voting, bots, host transfer and win conditions.
- `hooks/useParty.ts`: polling, retries, reconnection and server-clock alignment.
- `lib/game/result-card.ts`: downloadable result-card images.
- `worker/`: Cloudflare Worker entry point.
- `db/`, `drizzle/`: D1 schema and migrations, including migration metadata.
- `public/`, `vendor/`: assets and retained third-party licence notices. House art and animations are CSS; music is generated by Web Audio. There are no missing audio/image packs.
- `package.json`, `package-lock.json`: dependencies and exact resolved versions. `node_modules` is installed locally rather than bundled.
- `scripts/`, `vite.config.ts`: build and development support.
- `tests/game.test.mjs`: game rules and API tests, including concurrent joining.

## Run on your computer

Use Node.js **24.x** and npm. Node 24 is recommended for the included TypeScript-stripping test runner. Install Git if you want to publish changes.

1. Extract this ZIP and open a terminal **inside the `diwali-after-dark` folder**.
2. Run:

```sh
npm ci
npm run build
npm run db:local
npm run dev
```

3. Open the local URL printed by the development server (normally `http://localhost:5173`). No Cloudflare account or API key is needed for local gameplay.
4. Enter a name, click **Host a house party**, and add three or more optional bots to test on one device.
5. For human multiplayer testing, use separate browser profiles/devices. Tabs in the same browser share the saved seat. `localhost` on your friend's phone points at their phone, not your computer; deploy a test copy for cross-device play. HTTPS is recommended for UUID generation, sharing, audio and clipboard APIs.

`npm run db:local` uses migration tracking and is safe to rerun. Build before running it. Database files are created only under ignored `.wrangler/` state. If developing a new schema, edit `db/schema.ts`, run `npm run db:generate`, build, then apply migrations again. Never edit already-applied migrations.

```sh
npm test
npm run typecheck
npm run build
```

For a local preview of the production build, run `npm start` after building and applying local migrations.

## Game rules preserved

Search (90 seconds) → Blackout (25) → Discussion (75) → Vote (35). Default party clock: 20 minutes, adjustable by the host, followed by a final vote. Players search two locations per Search phase. Clues stay private until shared.

One Killer at 4–11 seats; two at 12–16. Detective at 4+, Protector at 5+, Witness at 6+, Archivist at 10+. Remaining players are Guests. Voting requires more than half of living players. Guests win when all Killers are removed. Killers win at parity, or by surviving the final vote. Protection can prevent an attack.

Host controls include bots, optional ghost takeover, pacing, restart and lobby removal. Eliminated players spectate. Recovery keys restore seats without accounts. Ghosts make simple random choices; they do not reason like human players.

## Multiplayer architecture and limits

The client polls the API roughly every 2.5 seconds, with network-latency clock correction. This is not a WebSocket or peer-to-peer game. The server stores each room as JSON in D1 and uses a versioned compare-and-swap update to prevent lost concurrent changes. Roles and private clues are filtered server-side for each seat.

The server is authoritative for deadlines. Phase advancement is checked when requests arrive; there is no background scheduler running while everyone is offline. On return, overdue transitions are evaluated. Room tokens and recovery keys grant access to seats: keep them private. There is currently no automatic room-data expiry. Public deployments should define a retention policy and add platform rate limiting if opening beyond friend groups.

Helper scripts also configure local Wrangler logs, caches and telemetry; these are tooling settings rather than application secrets.

## Hosting your own independent copy

GitHub stores this source. **GitHub Pages cannot run its Worker/D1 backend.** A GitHub push also does not automatically update the original ChatGPT-hosted site.

For an independent Cloudflare deployment:

1. Create/use your own Cloudflare account, then run `npx wrangler login`.
2. Run `npx wrangler d1 create diwali-after-dark`. Copy the database ID it returns.
3. Copy `deploy.example.json` to `deploy.local.json`. Set your own worker name, database name and returned database ID. This local file is ignored by Git.
4. Run:

```sh
npm run build
npm run deploy:prepare
npx wrangler d1 migrations apply DB --remote --config wrangler.deploy.json
npx wrangler deploy --config wrangler.deploy.json
```

5. Open the URL Wrangler returns. Host a room and join from a second device.

The preparation helper adjusts generated paths and binds your database. It does not publish anything itself. Rebuild and rerun `deploy:prepare` after source changes. The generated `wrangler.deploy.json` is ignored. Your account permissions, service availability, quotas and billing apply. This independent deployment procedure is provided but has **not** been deployed to your personal Cloudflare account.

Official references: [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/), [Wrangler D1 commands](https://developers.cloudflare.com/workers/wrangler/commands/d1/), [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/).

The original Site was published through managed Sites hosting, which provisioned D1, applied migrations and uploaded the Worker build. Its personal project ID, Git remote credentials and production data are deliberately absent from this export. `.openai/hosting.json` retains only generic storage binding declarations.

## Publish to GitHub

Create a new **public, empty** repository named `diwali-after-dark`. Do not initialise another README or licence there. Inside this extracted folder:

```sh
git init
git add .
git commit -m "Initial Diwali After Dark source"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/diwali-after-dark.git
git push -u origin main
```

Replace `YOUR_USERNAME`. Authenticate with GitHub's supported sign-in flow; never paste an access token into a source file or commit it.

Invite collaborators through your repository's access settings. Suggested workflow: each person creates a branch, pushes their changes and opens a pull request for review. Public visibility does not give strangers write access. A project-wide open-source licence has not been chosen on your behalf; decide that before inviting broad reuse, and retain all dependency/vendor licence notices.
